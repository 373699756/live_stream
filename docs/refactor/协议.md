# 协议模块重构计划

本文档记录后续协议栈重构计划。基准实现参考：

- `/home/c/linux/hisi/src/hisi_livestream/3rdparty/ZLMediaKit`
- 本仓库产品范围：只做 IPC 视频实时预览、抓图、配置和运维管理；不扩展音频、录像、
  存储回放、推流或无关 Web 功能。

## 目标

1. 先解决可复现的协议兼容问题，尤其是 VLC RTSP 拉流失败。
2. 以 ZLMediaKit 为结构参照，收敛 RTSP、HTTP-FLV、HLS、WebRTC 的媒体分发边界。
3. 把当前“各协议各自从 EncodedFrame 组包”的路径，逐步收敛为统一媒体源、统一 RTP
   packet、统一 reader/ring 分发模型。
4. 保持嵌入式约束：低内存、低拷贝、无异常、无 RTTI、失败路径明确。
5. 保留当前 WebRTC/net 已发现的 UDP peer 同步修复，但独立提交，不和 RTSP/媒体架构重构混合。

## ZLMediaKit 对照原则

ZLMediaKit 是结构和协议行为参照，不是代码复制目标。本项目只保留 video-only 预览能力，
不引入 ZLM 的推流、转码、录制、点播、音频、WebSocket 播放、RTMP、GB28181 等范围。

可借鉴的核心分层：

| ZLMediaKit 对照 | 本项目目标归属 | 借鉴点 | 本项目边界 |
| --- | --- | --- | --- |
| `Common/MediaSource` | `libs/media_source` | source 注册、reader/ring、ready、reader count、事件边界 | 不做全局 ServiceLocator，不暴露可变内部缓存 |
| `Common/MultiMediaSourceMuxer` | `media_pipeline -> media_source` | 一路输入驱动多协议缓存/输出 | 不做 RTMP/MP4/录制 mux |
| `Rtsp/RtspMuxer`、`Rtsp/RtpCodec`、`Rtsp/RtpPacket` | `libs/rtp` + `libs/media_source` | RTP packet 对象、时间戳、SDP、RTP ring | 只做 H.264/H.265 video RTP |
| `Rtsp/RtspMediaSourceImp` | `media_source` RTP view/ring | 已 packetize RTP 分发给 RTSP/WebRTC | 先保留 EncodedFrame reader，再分阶段引入 RTP reader |
| `Rtsp/RtspSession`、`RtspSplitter`、`UDPServer` | `libs/rtsp` | RTSP 方法分发、SETUP/PLAY 细节、UDP peer 探测、RTCP 统计 | 不实现 ANNOUNCE/RECORD/RTP over HTTP |
| `Http/HttpSession`、`HttpRequestSplitter`、`HttpFileManager` | `libs/http` | request splitter、session 生命周期、文件/短响应/长连接边界 | 控制 API 与媒体 handler 保持模块边界 |
| `Rtmp/FlvMuxer`、`Record/HlsMaker`、`HlsMediaSource` | `media_source` + `http_media` | FLV/HLS 缓存和 HTTP 输出分离 | 不实现 RTMP、MP4、录像 |
| `webrtc/WebRtcSession`、`WebRtcTransport`、`IceSession`、`DtlsTransport`、`SrtpSession` | `libs/webrtc` | SDP/ICE/DTLS/SRTP/RTCP 分层 | 不处理公网扫码和云中继，本轮只优化本地 WebRTC |

## 目标功能划分

### `net`

定位：只拥有 TCP/UDP endpoint、event loop、timer、send queue、socket diagnostics。

建议拆分：

- `tcp_server.*`：listen、accept、connection id 分配、connection close 汇总。
- `tcp_connection.*`：read buffer、send queue、pending bytes、stall timeout、close after send。
- `udp_endpoint.*`：bind、sendto/sendmsg、peer 更新、UDP diagnostics。
- `net_buffer_slices.*`：slice/owner 引用计数，统一支持 RTP、HLS segment、FLV tag。
- `net_diagnostics.*`：connection/socket 诊断 DTO，供 HTTP/RTSP/WebRTC 聚合。

关键函数边界：

- `ListenTcp()` 只创建 listener，不注册业务 handler 逻辑。
- `SendSlices()` 只处理 socket 队列和 owner 生命周期，不理解 HTTP/RTSP/RTP。
- `SetPeer()` 必须同步更新 UDP peer；WebRTC ICE 选中 pair 后 DTLS 可能马上发送。
- `PendingBytes()`、`GetConnectionDiagnostics()` 不触碰业务模块。

优化点：

- send queue 按连接限额，超过阈值只关闭慢连接，不阻塞 event loop。
- `sendmsg()`/scatter-gather 作为 RTP/FLV/HLS 热路径默认发送方式。
- UDP/TCP 发送失败日志保留 errno、connection/socket id、peer 和 pending bytes。

### `media_source`

定位：拥有所有协议共享的媒体状态、cache、reader/ring、ready、时间戳修正。

建议拆分：

- `media_source.cpp`：public API 和 stream state 编排。
- `stream_state.*`：每路 `main/sub` 的 running、track、codec generation、reset reason。
- `frame_ring.*`：EncodedFrame reader、GOP cache、live queue、slow reader。
- `timestamp_corrector.*`：按 ZLM `Stamp/DeltaStamp` 思路处理回退、跳变、relative timestamp。
- `flv_cache.*`：FLV sequence header、metadata、GOP tags。
- `hls_segmenter.*`：segment append、playlist、segment retain、淘汰。
- `mjpeg_cache.*`：latest JPEG frame 和 ready。
- `rtp_ring.*`：后续阶段新增，保存 video RTP packet view/ring。
- `media_source_diagnostics.*`：reader count、cached bytes、slow reader、last dts。

关键函数边界：

- `InputFrame()`：唯一上游入口，完成 timestamp correct、track update、cache update、reader fanout。
- `AttachFrameReader()`：创建 reader，决定是否 keyframe-first。
- `GetFrameReaderStartData()`：只返回启动所需 track/GOP，不暴露内部可变缓存。
- `PopFrameReaderFrame()`：拉 live frame，失败只表示暂时无帧或 reader 已关闭。
- `DetachFrameReader()`：释放 reader queue 和引用。
- `BuildFlvStartData()`、`ReadHlsPlaylist()`、`ReadHlsSegment()`：只读 cache，HTTP 不参与生成。
- `BuildRtpStartData()`、`PopRtpPacket()`：后续 RTP ring 阶段新增，供 RTSP/WebRTC 共享。

优化点：

- 热路径只 retain/unref `VideoBuffer`，不复制帧 payload。
- GOP cache、reader live queue、HLS retain、FLV clients 都有明确上限。
- codec 切换、stream stop、timestamp reset 一次性重建相关缓存和 ready 状态。
- reader 慢时清空该 reader queue 并等待下一个关键帧，不影响其他协议客户端。

### `rtp`

定位：只做 video RTP packetization、packet view、SDP codec 文本、RTCP 基础解析。

建议拆分：

- `rtp_packet_view.*`：RTP header、payload slices、marker、sequence、timestamp、ssrc。
- `rtp_packetizer.*`：H.264/H.265 AnnexB 到 RTP packet，FU-A/FU payload 分片。
- `rtp_codec_h264.*`、`rtp_codec_h265.*`：NALU 边界、payload header、SDP fmtp 辅助。
- `rtp_timestamp.*`：PTS us 与 90k RTP timestamp 换算。
- `rtcp_parser.*`：RR/PLI/FIR/NACK/TWCC 基础识别，先只输出事件和计数。

关键函数边界：

- `PacketizeFrame(input, sink)`：无 socket、无 session、无锁外副作用。
- `BuildVideoSdp(track, ssrc)`：只处理 video track SDP，不生成 RTSP 响应。
- `RtpTimestampFromPts(pts_us)`：统一 RTSP/WebRTC timestamp 算法。
- `ParseRtcpPacket()`：返回结构化反馈，具体动作由 RTSP/WebRTC 决定。

优化点：

- RTP header 和 FU header 使用栈内小 buffer，payload 仍指向 `VideoBuffer`。
- 分片 MTU 来自配置，RTSP/WebRTC 共用，避免两套 H.264/H.265 分片逻辑。
- packetizer 不持有 session 状态，sequence/ssrc/payload type 由调用方传入。

### `rtsp`

定位：拥有 RTSP 控制连接、RTSP session 状态、认证、SETUP/PLAY/TEARDOWN、
TCP interleaved/UDP transport 和 RTCP 统计。

建议拆分：

- `rtsp.cpp`：service 生命周期、listener、依赖注入、session store 汇总。
- `rtsp_session.*`：单连接状态，包含 stream、transport、reader、sequence、ssrc、diagnostics。
- `rtsp_splitter.*`：RTSP request 与 TCP interleaved frame 切包。
- `rtsp_request_dispatcher.*`：方法表分发，借鉴 ZLM `handleReq_*`，不直接访问 net。
- `rtsp_describe_handler.*`：DESCRIBE、SDP、track ready、Content-Base。
- `rtsp_setup_handler.*`：Transport 解析、TCP/UDP setup、ssrc、server_port、UDP socket。
- `rtsp_play_handler.*`：PLAY 状态机、reader attach、RTP-Info、Range、arm drain。
- `rtsp_udp_peer.*`：UDP peer 探测、RTCP/RTP 来源地址学习。
- `rtsp_transport.*`：TCP interleaved 和 UDP RTP/RTCP send。
- `rtsp_rtp_sender.*`：从 reader/RTP ring 取包并调用 transport。
- `rtsp_diagnostics.*`：session diagnostics DTO。

关键函数边界：

- `OnRtspRequest(session, request)`：只做方法分发和状态码归口。
- `HandleDescribe()`：只读 track，返回 SDP；track 未 ready 返回 455。
- `HandleSetup()`：只协商 transport；重新 SETUP 必须清理旧 reader/UDP socket。
- `ParseTransportHeader()`：输出结构化 TCP/UDP/multicast/unsupported 结果。
- `BuildSetupTransportResponse()`：统一生成 ZLM 风格 `Transport` header。
- `StartPlayback()`：attach reader/start data，不发送 PLAY 响应。
- `BuildPlayHeaders()`：生成 `Session`、`Range`、`RTP-Info`。
- `ArmPlaybackDrain()`：PLAY 200 响应入队后再启动发送。
- `SendRtpPacket()`：只取 session transport 快照，锁外发送。
- `OnUdpPacket()`：RTCP 统计和 UDP peer 学习，不做码率控制。
- `CloseSessionResources()`：统一 detach reader、cancel timer、close UDP。

协议实现细节：

- OPTIONS：返回 `OPTIONS, DESCRIBE, SETUP, PLAY, TEARDOWN`。
- DESCRIBE：stream 不存在 404，track 未 ready 455；SDP 只包含 video track。
- SETUP TCP：响应 `RTP/AVP/TCP;unicast;interleaved=0-1;ssrc=<hex>`。
- SETUP UDP：响应 `RTP/AVP/UDP;unicast;client_port=a-b;server_port=c-d;ssrc=<hex>`。
- PLAY：先准备 reader/start data，再返回 200；header 包含 `Range` 和完整 `RTP-Info`。
- RTP-Info：`url=<control-url>;seq=<next-seq>;rtptime=<first-rtp-timestamp>`。
- TEARDOWN：响应后关闭控制连接，资源释放走统一 close path。

优化点：

- RTSP mutex 只保护 session 状态，不在持锁状态下调用 net send。
- start GOP 逐帧 move 出队，发送后立即 unref。
- UDP send 失败先记录 errno 和 peer，再按错误类型决定关闭或继续。
- RTSP session 统计区分 RTP packet、RTP bytes、RTCP packet、pending bytes、close reason。

### `http`

定位：拥有 HTTP 连接、request splitter、router、认证、静态文件、控制 API DTO、
普通响应 writer 和媒体 streaming writer。

建议拆分：

- `http.cpp`：service 生命周期、listener、handler 注册。
- `http_session.*`：单连接状态、keep-alive、streaming 状态、request buffer。
- `http_request_splitter.*`：header/body 切包，借鉴 ZLM `HttpRequestSplitter`。
- `http_router.*`：method/path 匹配，不包含业务逻辑。
- `http_response_writer.*`：JSON/短响应/静态文件/HLS segment 发送。
- `http_stream_writer.*`：HTTP-FLV/MJPEG/SSE 长连接发送、close callback、diagnostics。
- `http_static_file.*`：静态文件路径解析、content type、range 如后续需要再加。
- `http_auth_filter.*`：cookie/bearer 鉴权，输出 request context。
- `http_api_handlers.*`：控制 API DTO，可继续按 auth/config/media/system/ai 拆文件。
- `http_diagnostics.*`：HTTP connection 和 streaming session diagnostics。

关键函数边界：

- `OnTcpRead()`：只喂 splitter，不直接执行业务。
- `OnRequestHeader()`：校验 header size、method、path、body size。
- `DispatchRequest()`：router 找 handler，返回明确 `HttpHandlerResult`。
- `SendResponse()`：短响应统一入口，决定 content-length/keep-alive/close-after-send。
- `BeginStreaming()`：连接从普通 HTTP 状态转入 streaming 状态。
- `AttachStreamingClient()`：绑定 `http_media` client id 和 close callback。
- `EnqueueStreamingSlices()`：只提交 slices，不读取媒体源。
- `CloseStreamingSession()`：关闭 TCP 后触发 detach，不让 http_media 自己关 socket。

优化点：

- 控制 API 和 streaming send 分 executor/队列，避免直播写阻塞登录/配置。
- HLS segment 作为短响应走 `SendResponseSlices()`，不进入 streaming session。
- HTTP-FLV/MJPEG/SSE 必须有 send queue 上限和 idle/stall timeout。
- `/api/media/sessions` 能看到 opening/attached/closing/closed 和 pending bytes。

### `http_media`

定位：只拥有 HTTP 媒体路由 handler、WebRTC signaling DTO、媒体 client attach/detach。

建议拆分：

- `hls_handler.*`：playlist/segment handler，短响应。
- `http_flv_session.*`：FLV 长连接 session，header/GOP/start data/live reader。
- `mjpeg_session.*`：MJPEG multipart 长连接。
- `sse_event_session.*`：事件流订阅和 detach。
- `webrtc_signaling_handler.*`：JSON signaling DTO。
- `whep_handler.*`：后续可选，当前不作为第一批要求。
- `http_media_diagnostics.*`：媒体 session 聚合。

关键函数边界：

- `HandleHlsPlaylist()`、`HandleHlsSegment()`：只读 `media_source`，返回短响应。
- `StartHttpFlv()`：begin stream、读取 FLV start data、attach media client。
- `DrainHttpFlvClient()`：从 reader/cache 取 slice，交给 `HttpMediaWriter`。
- `StartMjpeg()`：begin multipart stream，attach MJPEG client。
- `OnHttpStreamClosed()`：detach 对应 media client，释放引用。
- `HandleCreateWebrtcPeer()`、`HandleOffer()`、`HandleCandidate()`、`HandleClosePeer()`：
  只做 DTO 与 `IWebrtc` 调用。

优化点：

- HTTP-FLV GOP/start data 只复制小 header，payload 通过 owner 引用。
- HLS playlist 只发布已完成 segment，避免客户端请求半成品。
- FLV/MJPEG 慢客户端关闭只影响当前 client，不回压 `media_source`。
- handler 不解析设备 SDK 配置，不推导 codec ready。

### `webrtc`

定位：拥有本地 WebRTC peer、SDP、ICE、DTLS、SRTP、RTCP 和 RTP 发送。

建议拆分：

- `webrtc.cpp`：service facade、peer store、options apply、stats。
- `webrtc_peer.*`：peer 生命周期、state、diagnostics、reader id。
- `sdp_session.*`：offer parse、answer build、payload/ssrc/fingerprint。
- `ice_transport.*`：STUN binding、candidate、selected pair。
- `dtls_transport.*`：certificate、fingerprint、handshake、SRTP key export。
- `srtp_session.*`：RTP/SRTCP protect/unprotect。
- `webrtc_transport.*`：UDP endpoint、ICE/DTLS/SRTP 收发编排。
- `webrtc_rtp_sender.*`：reader/RTP ring 到 SRTP packet。
- `rtcp_feedback.*`：PLI/FIR/NACK/TWCC 解析和计数。
- `webrtc_diagnostics.*`：peer diagnostics DTO。

关键函数边界：

- `CreatePeer()`：只创建 peer 状态，不隐式启动媒体发送。
- `ApplyOffer()`：解析 SDP、生成 answer、创建 transport。
- `AddRemoteCandidate()`：只进入 ICE transport，不触碰 RTP sender。
- `OnUdpPacket()`：按 STUN/DTLS/SRTCP 分类分发。
- `OnDtlsConnected()`：导出 SRTP key，标记 transport ready。
- `AttachMediaReader()`：peer connected 后 attach keyframe-first reader。
- `DrainPeerFrames()`：从 reader/RTP ring 拉包，加密后发送。
- `ClosePeer()`：统一取消 timer、detach reader、关闭 transport。

优化点：

- `SetPeer()` 同步更新 UDP peer，避免 ICE selected 后 DTLS 首包丢失。
- SRTP 输出 buffer 每 peer 复用，不为每包分配 vector。
- PLI/FIR 触发 `RequestKeyFrame()`；NACK/TWCC 先计数，重传/拥塞控制后续单独做。
- 本轮不做公网扫码、TURN/SFU、云信令。

## 当前主要问题

### RTSP

- SETUP UDP 响应使用 `RTP/AVP;unicast`，ZLMediaKit 使用
  `RTP/AVP/UDP;unicast`，部分客户端兼容性更差。
- SETUP 响应缺少 `ssrc`，不利于客户端建立 RTP session 预期。
- PLAY 响应只有 `RTP-Info: url=/live/main`，缺少 `seq` 和 `rtptime`。
  VLC 在 PLAY 后立即断开时，这比 UDP send 失败更像兼容触发点。
- 当前 RTSP 仍在 session 内直接 packetize `EncodedFrame`，而 ZLMediaKit 是
  `RtspMediaSource/Ring` 分发已构造好的 RTP packet。
- UDP 模式缺少 ZLMediaKit 的 peer UDP 探测/NAT 映射校正能力。当前只按 SETUP
  `client_port` 发送，跨 NAT 或客户端端口映射时容易失败。

### 媒体源与 fanout

- `media_source` 已有 reader/GOP/cache，但 RTP packet 仍由 RTSP/WebRTC 分别构造。
- RTSP、WebRTC 共享 H.264/H.265 RTP packetization 逻辑，但发送状态、sequence、
  timestamp、SSRC 和统计分散在各自模块。
- HTTP-FLV、HLS、MJPEG 和 RTP 协议链路共享同一上游帧，但缓存生命周期、ready 状态、
  慢客户端处理还没有形成 ZLMediaKit 那种清晰的 MediaSource/Ring 分层。

### HTTP-FLV/HLS

- 当前功能可用，但模块边界偏“handler 拉缓存”，缺少统一 session/read ring 视角。
- HLS segment、FLV header/GOP cache 与媒体源状态强相关，后续应继续归 `media_source`，
  HTTP 层只做协议响应、鉴权和 socket 生命周期。

### HTTP

- `http` 当前是宽依赖模块，承担 HTTP server、router、鉴权、静态文件、控制 API 和
  媒体长连接 writer 边界，职责可以继续拆细，但不能让业务模块反向依赖 HTTP。
- 普通控制 API 和直播长连接需要更明确的 executor/queue/backpressure 边界，避免
  HTTP-FLV、MJPEG、SSE 或大 HLS segment 发送阻塞配置、登录、状态查询等控制请求。
- `HttpMediaWriter` 是 `http` 与 `http_media` 的关键边界，应只暴露流式会话句柄、
  slice 写入、关闭回调和诊断，不把 socket 队列、net connection 或媒体内部锁泄漏给
  `http_media`。
- HTTP request splitter、keep-alive、timeout、body size、send queue 上限和慢客户端关闭
  应按 ZLMediaKit 的 session 生命周期思路收敛，但不能照搬第三方框架。

### WebRTC

- 已发现 `UdpEndpoint::SetPeer()` 异步更新会导致 ICE 选中 peer 后 DTLS 立即发送失败。
  该修复应保留并单独提交。
- 当前设备端只发布 host candidate，不具备公网 NAT 穿透的完整能力。
- 扫码远程预览和公网访问不是本轮冻结范围，后续单独立项，不放进本轮协议重构阶段。

### 模块结构

- 当前协议模块可运行，但相比 ZLMediaKit，职责拆分还不够细：
  `Session`、`MediaSource`、`Muxer/Packetizer`、`Transport`、`Ring/Reader`、
  `Protocol Handler` 的边界需要继续收敛。
- 后续不新增 legacy adapter、wrapper、bridge 来同时维护两套路径；重构到目标接口后同步删除旧路径。

## 分阶段计划

### 阶段 1：RTSP wire 兼容修复

目标是先让 VLC/常见客户端更稳定拉流，控制改动面。

- SETUP TCP 响应补 `ssrc`：
  `RTP/AVP/TCP;unicast;interleaved=0-1;ssrc=<hex>`。
- SETUP UDP 响应改为：
  `RTP/AVP/UDP;unicast;client_port=a-b;server_port=c-d;ssrc=<hex>`。
- PLAY 响应补齐：
  `Range: npt=0.000-`。
- PLAY `RTP-Info` 使用完整形式：
  `url=<control-url>;seq=<next-seq>;rtptime=<initial-rtp-time>`。
- `seq` 取当前 session 下一包 RTP sequence，`rtptime` 取启动 GOP 首帧 corrected
  PTS 换算后的 90k timestamp；没有启动帧时用当前 session 初始 RTP timestamp。
- UDP RTP 发送失败不直接掩盖；先增加可定位错误日志，再根据错误类型判断是否关闭控制连接。
- 验证：
  `make -j2`、`make host-test`、VLC TCP/UDP 拉 `/live/main` 和 `/live/sub`。

### 阶段 2：RTSP UDP/NAT 行为对齐 ZLMediaKit

目标是补齐 UDP 模式真实网络行为。

- SETUP 后绑定 RTP/RTCP socket，并记录 client_port。
- 监听客户端发来的 RTCP/RTP 探测包，必要时用实际来源地址和端口更新 UDP peer。
- 区分控制连接 peer、SETUP client_port peer、UDP 实际 peer，命名必须直指语义。
- RTCP receiver report 先只做统计和 peer 发现，不做码率控制。
- 验证：
  同网段 VLC UDP、跨 NAT 端口映射场景、异常 client_port。

### 阶段 3：HTTP 核心模块优化

目标是先把 HTTP server/router/writer 边界收敛清楚，为后续 HTTP-FLV/HLS/MJPEG
优化提供稳定底座。

- 拆清 HTTP 内部职责：
  request splitter 只负责 HTTP message 边界，server/session 负责连接生命周期，
  router 负责路径分发，handler 只做 DTO 和业务调用，writer 负责响应组包和背压。
- 明确普通控制 API 与流式媒体输出的执行边界：
  控制请求不能被直播写阻塞；流式输出必须受 send queue、buffer limit 和 timeout 保护。
- 收敛 `HttpMediaWriter`：
  只暴露 begin stream、attach client、enqueue slices、close callback 和 streaming diagnostics。
- 完善 HTTP streaming 状态机：
  区分 `not_handled`、`response_sent`、`streaming`、`closed`、`failed`，避免短响应和长连接
  接管路径混在一起。
- 静态文件、JSON API、HLS segment 这类短响应使用统一响应路径；HTTP-FLV、MJPEG、SSE
  使用长连接 streaming 路径。
- 诊断补齐 connection id、client ip、local/remote address、pending bytes、
  send queue length、last write time 和 close reason。
- 验证：
  登录/API/静态文件、HLS 短响应、HTTP-FLV/MJPEG 长连接、慢客户端、断连和 keep-alive。

### 阶段 4：统一 RTP packet 输出层

目标是把 RTSP/WebRTC 重复 packetization 收敛。

- 在 `media_source` 或相邻 RTP 模块引入 video-only RTP packet 输出契约。
- 保留协议私有的 sequence、SSRC、payload type、SRTP/TCP interleaved 差异。
- RTP packet view 仍使用 slice/owner 模型，避免热路径复制大 payload。
- RTSP 发送 plain RTP；WebRTC 在同一 RTP packet 基础上执行 SRTP 加密。
- 明确 timestamp 使用 `media_source` corrected PTS，统一 90k clock。
- 验证：
  H.264/H.265 大帧分片、关键帧门禁、sequence 连续性、WebRTC SRTP 发送。

### 阶段 5：MediaSource/Ring 分发结构对齐

目标是向 ZLMediaKit 的 `MediaSource + Ring reader` 结构靠拢。

- `media_source` 继续拥有 GOP cache、reader、HLS、FLV sequence/header、runtime ready。
- 每个协议 session/peer 持有 reader id，不注册全局 push sink。
- reader 创建、启动 GOP、live queue、慢客户端、detach 路径全部由 `media_source`
  统一维护。
- 协议层只处理：
  连接生命周期、鉴权、请求解析、协议响应、transport 发送、协议统计。
- 验证：
  多 RTSP、多 HTTP-FLV、多 WebRTC 同时拉流时 reader count 可控，慢客户端不会拖垮上游。

### 阶段 6：HTTP-FLV/HLS 模块收敛

目标是让 HTTP 层只做 HTTP 协议，不持有媒体内部状态。

- HTTP-FLV session 从 `media_source` 获取 FLV header 和 GOP 起点，再进入 live reader。
- HLS handler 只读取已完成 playlist/segment；segment 生成、淘汰和 ready 状态归
  `media_source`。
- MJPEG session 与 HTTP-FLV 一样走 `HttpMediaWriter` 长连接路径，断连时统一 detach client。
- `http_media` 不直接接触 socket 队列，不持有 net connection，不解析设备 SDK 配置，
  不推导 codec ready。
- `/api/media/sessions` 聚合 HTTP streaming diagnostics，HLS playlist/segment 作为短响应，
  不作为常驻 session 展示。
- 验证：
  Web 预览、curl 拉 FLV、MJPEG、HLS playlist/segment、codec 切换、stream stop/start。

### 阶段 7：协议诊断和验收

- `/api/media/sessions` 区分 RTSP、WebRTC、HTTP-FLV、HLS session/reader 状态。
- 关键字段：
  session id、stream、transport、reader id、pending bytes、RTP/RTCP 计数、
  last error、close reason、selected ICE pair、relay/direct 模式。
- 日志只保留启动、停止、配置变化、错误和关键状态变化；不长期保留高频帧日志。
- 验证：
  `make -j2`、`make host-test`、板端 RTSP/VLC、WebRTC 浏览器预览、
  HTTP-FLV/HLS、慢客户端、断网重连。

## 暂不处理项

- WebRTC 内网扫码、公网访问、腾讯云信令、TURN/SFU/relay 和设备云绑定不属于本轮
  协议重构冻结范围。后续需要时单独立项，先明确云端架构、安全模型、设备绑定流程和成本边界。

## 执行原则

- 每个阶段完成后立即验证并提交，不把无关模块混入同一提交。
- 先修可复现 bug，再做结构性收敛。
- 所有 public API、配置 schema、HTTP API 变化必须同步调用方和模块文档。
- 不修改 `3rdparty/ZLMediaKit`，只把它作为行为和结构参照。
- 不主动改测试目录；如果某阶段必须补测试，先明确测试目标后再动。
