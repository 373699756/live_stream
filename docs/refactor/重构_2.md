# 基于 ZLMediaKit 细节的媒体内核与 HTTP/Web API 完全重构计划

## Summary

本轮以当前任务 12 后的仓库为新基线，进行第二阶段完全重构：媒体内核、
HTTP/RTSP/HLS/FLV/WebRTC、视频内存管理、HTTP/Web API 一起收敛。实现时严格参考
本地 ZLMediaKit 相关源码的成熟细节，但只裁剪到本项目 IPC video-only 场景。

参考重点：

- 媒体模型：`MediaSource`、`MultiMediaSourceMuxer`、`Frame`、`Track`
- 时间戳：`Stamp`、`DeltaStamp`
- HLS：`HlsMaker`
- FLV：`FlvMuxer`
- RTSP/RTP：`RtspSession`、`RtspMuxer`、`RtpCodec`
- WebRTC：`WebRtcSession`、`WebRtcTransport`
- HTTP/API：`WebApi`、`HttpSession`、`HttpFileManager`
- 网络/内存：ZLToolKit `EventPoller`、`TcpServer`、`Session`、`Buffer`

不嵌入 ZLMediaKit，不启动 MediaServer，不引入音频、录制、回放、推流、代理、
TURN、datachannel 或通用媒体服务器管理台。

## Architecture Changes

- `media_source` 收敛为 ZLM `MediaSource + RingBuffer + Stamp` 的裁剪版：唯一媒体
  状态中心，拥有 video track、corrected DTS/PTS、GOP cache、reader ring、HLS
  segment、FLV 起播缓存、MJPEG latest frame 和资源统计。
- `media_codec` 只做 H264/H265 AnnexB 解析、AVCC/HVCC 等 codec 工具；`rtp`
  只做 RTSP/WebRTC 共用 RTP packet view。旧 `media_mux` 不再作为独立模块目标。
- `http_media` 专管媒体 HTTP：HLS、HTTP-FLV、MJPEG、WebRTC signaling/WHEP；
  控制 API 仍归 `http`。
- `rtsp` 专管 RTSP session、SDP、RTP over TCP/UDP、reader 生命周期；ONVIF 和 Web
  只能通过后端 URL helper 获取 RTSP URL。
- `webrtc` 分层为 service/signaling、session、transport、RTP sender：session 持
  SDP/RTP 参数，transport 持 ICE/DTLS/SRTP/UDP/timer，service 持 media reader 和
  drain timer。
- `net` 统一所有 TCP 背压：send queue、pending bytes、stall timeout、
  read/write timeout、close reason。协议模块只提交 slice/view 和 owner 引用。

## Media Implementation

- `MediaFrame` 是协议热路径唯一帧对象，携带 `EncodedFrame` 引用、stream、codec、
  keyframe、track、DTS/PTS、duration。
- `TimestampCorrector` 按 ZLM `Stamp/DeltaStamp` 增强：处理时间戳回退、跳变、
  relative timestamp、stream stop、codec 切换和 reset。
- 所有协议输出统一使用 corrected DTS/PTS；不得各协议私自修正时间戳。
- 删除生产协议对旧 push sink 的依赖；RTSP/WebRTC/HTTP-FLV/MJPEG 均使用
  reader/client id。
- codec 切换、stream stop、timestamp reset 时清空 GOP、FLV sequence header、
  HLS current segment、reader live queue 和 ready 状态。

## Protocol Details

- HLS 按 ZLM `HlsMaker`：只在关键帧尝试切片；时间戳回退时重置切片计时；先
  finalize segment body，再更新 playlist；playlist 只暴露完整 segment；实际 retain
  数量大于 playlist depth，避免播放器刚读到索引就取不到 segment。
- FLV 按 ZLM `FlvMuxer`：起播顺序固定为 FLV header、metadata/sequence header、
  cached GOP、live tag；tag header、payload、previous tag size 用 slices 输出；
  payload 通过 `VideoBuffer` owner 保活，不复制整帧。
- MJPEG 只服务 MJPEG codec，不做转码。
- RTSP 按 ZLM `RtspSession/RtspMuxer/RtpCodec`：DESCRIBE 只使用 ready video track；
  SSRC 非 0；RTP timestamp 使用 90k PTS；TCP interleaved/UDP transport 只负责发送
  `RtpPacketView`；TEARDOWN/断连/SETUP 切换统一 cancel timer、detach reader、
  close UDP socket。
- WebRTC 按 ZLM `WebRtcSession/WebRtcTransport`：ICE selected pair 后才处理
  DTLS/SRTP；DTLS retransmit timer 必须可 cancel；SRTP 初始化失败、DTLS failed、
  setup timeout 走同一 peer close path；PLI/FIR 触发 `RequestKeyFrame`，
  NACK/TWCC 只识别不实现重传/拥塞控制。

## HTTP/Web API Redesign

- 允许删除旧 Web API 路径和 DTO，不保留 alias。
- 所有 JSON API 统一响应：`{ ok, data, error, request_id }`。失败使用明确
  `error.code` 和 `error.message`。
- 统一 stream 标识为 `main|sub`；不暴露 ZLM `vhost/app`，内部可映射为
  `live/main`、`live/sub`。
- 新 API 分组：
  - `/api/auth/*`
  - `/api/config/*`
  - `/api/media/streams`
  - `/api/media/streams/{stream}`
  - `/api/media/streams/{stream}/urls`
  - `/api/media/sessions`
  - `/api/webrtc/peers`
  - `/api/system/*`
  - `/api/operations/*`
  - `/api/upgrade/*`
  - `/api/ai/*`
- 播放 URL 与 JSON API 分离：
  - HLS：`/live/{stream}/hls/index.m3u8`、`/live/{stream}/hls/seg-{sequence}.ts`
  - HTTP-FLV：`/live/{stream}.live.flv`
  - MJPEG：`/live/{stream}.mjpg`
  - Snapshot：`/snapshot/{stream}.jpg`
  - RTSP URL 由后端根据 host、端口、auth 配置生成，Web 不再拼接。
- WebRTC JSON API：
  - `POST /api/webrtc/peers`
  - `POST /api/webrtc/peers/{peer_id}/offer`
  - `POST /api/webrtc/peers/{peer_id}/candidates`
  - `DELETE /api/webrtc/peers/{peer_id}`
- 可选 WHEP 播放入口：`POST /live/{stream}/whep`，body 为 SDP offer，返回
  `application/sdp`，`Location` 指向删除 URL。

## Web Console Changes

- `www/src/api/types.ts` 重建媒体 DTO：`MediaStreamRuntime`、`MediaPlaybackUrls`、
  `MediaSessionInfo`、`WebrtcPeerInfo`。
- `VideoPreview` 只读 `/api/media/streams` 和 `/api/media/streams/{stream}/urls`，
  不再从 status/capabilities/local helper 拼状态。
- WebRTC hook 改用 RESTful peer 路径；关闭用 `DELETE /api/webrtc/peers/{peer_id}`。
- `StreamInfoPage` 展示后端返回的 RTSP/HLS/FLV/MJPEG/WebRTC/snapshot URL 和协议状态。
- mock 数据按新 envelope 和 DTO 重建；删除 Web 对旧 `/api/status/streams`、旧媒体
  URL helper 的依赖。

## Diagnostics And Memory Gates

- `media_source` 暴露 runtime snapshot：track ready、codec、running、protocol ready、
  reader/client count、cached frames/bytes、HLS bytes、last DTS、last reset reason。
- `rtsp` 暴露 session diagnostics：session id、stream、transport、remote/local address、
  reader id、pending bytes、RTP packets/bytes、close reason。
- `webrtc` 暴露 peer diagnostics：state、stream、ICE selected、DTLS state、SRTP ready、
  packets/bytes、last error、created/updated timestamp。
- `net/http` 暴露 connection diagnostics：connection id、owner protocol、
  remote/local address、pending bytes、send queue length、close reason。
- 所有 streaming send path 使用 slice + `NetBufferOwner`，不得拼接临时大 buffer。
- 慢客户端触发 queue full、pending limit、send stall、write timeout 后必须关闭并释放
  reader/client。

## 多 Codex 并行任务计划

本节用于多个 Codex 实例并行执行上面的重构。拆分原则是：先串行冻结跨模块契约，
再按文件所有权并行实现，最后串行集成清理。任何实例都不得为了临时跑通在本模块
内复制一份跨模块类型、DTO、URL helper 或兼容 alias。

### 并行通用规则

- 每个 Codex 独立分支工作，分支名建议 `refactor/media-core`、
  `refactor/http-api` 这类能对应任务卡的名字。
- 每个 Codex 开工前读取 `AGENTS.md`、`docs/README.md`、`重构_2.md` 和自己拥有
  模块的 `docs/libs/*.md` 或 `docs/web/*.md`。
- 公共契约只允许契约拥有者修改：`include/*.h`、HTTP JSON DTO、错误码、播放 URL
  规则和跨模块回调签名冻结后，依赖方只能按契约实现，不能在本模块添加影子类型。
- `重构_2.md` 在并行开发期间只由协调 Codex 修改；其他 Codex 把计划偏差写入自己
  模块文档，合并时再由协调 Codex 同步总计划。
- 破坏式重构不保留旧路径：不得新增旧 API alias、旧 DTO adapter、旧播放 URL helper
  或旧 push sink 兼容层。
- 测试目录默认不改；除非任务卡明确要求，验证以生产代码构建、模块构建、Web build
  和运行检查为主。
- 涉及同一个 public header 的变更必须串行合并；依赖方如果被阻塞，只先完成内部
  实现或文档 TODO，不抢先改 header。
- API schema 变更流程固定为：`Codex-HttpAPI` 先更新后端契约文档和 envelope，
  `Codex-WebConsole` 再按同一 schema 更新 TypeScript DTO、mock 和 UI。
- 每个任务完成后立即提交，提交信息使用 Conventional Commits，例如
  `refactor(media-source): replace push sinks with readers`。

### 任务 1A: Codex-MediaCore

**目标**

- 按 ZLMediaKit `MediaSource + RingBuffer + Stamp` 思路收敛媒体状态中心。
- 所有协议只从 `media_source` 读取 corrected frame，不再各自维护时间戳修正和旧
  push sink 状态。

**拥有路径**

- `libs/media_source/include/media_frame.h`
- `libs/media_source/include/timestamp_corrector.h`
- `libs/media_source/include/media_source.h`
- `libs/media_source/src/*`
- `libs/media_pipeline/include/media_pipeline.h`
- `libs/media_pipeline/src/*`
- `docs/libs/media_source.md`
- `docs/libs/media_pipeline.md`
- `docs/optimization/memory.md`

**依赖输入**

- 任务 0 冻结的 `MediaFrame`、reader、runtime snapshot 字段。
- `device` 输出的 encoded video frame 语义。
- `media_codec` 的 AnnexB/codec 参数解析契约。

**核心实现点**

- `MediaFrame` 保留 `EncodedFrame` owner 引用，携带 stream、codec、track、
  keyframe、DTS、PTS、duration，避免协议层复制大帧。
- `TimestampCorrector` 处理时间戳回退、跳变、relative timestamp、stream stop、
  codec 切换和 reset；所有协议只消费 corrected DTS/PTS。
- `MediaSource` 持有 GOP cache、reader ring、latest MJPEG frame、HLS/FLV ready 状态、
  reader/client 统计和最后 reset reason。
- codec 切换、stream stop、timestamp reset 时集中清理 GOP、FLV sequence header、
  HLS current segment、reader live queue、protocol ready。
- reader attach/detach 必须返回稳定 reader id，断连后 reader count 和缓存引用回落。

**不要触碰**

- 不改 `libs/http_media`、`libs/rtsp`、`libs/webrtc` 的协议发送逻辑；只保留必要的
  编译修复接口。
- 不改 HTTP JSON API 和 Web DTO。
- 不在 `media_pipeline` 里新增协议专用缓存。

### 任务 1B: Codex-NetBackpressure

### 任务 2A: Codex-HttpMedia

**目标**
